# Goal

Back the Phase 1 agent-runtime registry work with a repo-native REQ so the architecture slice follows Harness Engineering traceability rules.

This REQ covers turning `harness/CAPABILITIES.md` and `harness/CONNECTORS.md` into executable runtime contracts under `src/agent-runtime/`, while preserving the existing harness naming as the document-facing source of truth.

## In Scope

- typed capability registry schema and loader
- typed connector registry schema and loader
- canonical dot-format ids plus legacy-id lookup compatibility
- validation entrypoint for registry loading
- regression coverage for aliases, backend validation, multiline list items, and doc-compliance script behavior
- CI and local pre-merge gate alignment for `npm run validate`
- Phase 1 architecture doc and before/after diagrams

## Out of Scope

- mailbox service implementation
- task runtime or workflow state machine extraction
- worker runtime migration out of shell
- renaming existing capability ids in harness markdown

## Acceptance Criteria

1. `harness/CAPABILITIES.md` spec blocks load into a typed Node.js registry.
2. `harness/CONNECTORS.md` spec blocks load into a typed Node.js registry and resolve to existing capabilities.
3. Legacy ids and canonical dot-format ids both resolve through runtime lookup.
4. `scripts/validate-agent-runtime-registry.ts` succeeds locally and in CI.
5. Regression coverage exists for alias loading, backend-id safety, multiline YAML list items, and doc-compliance gate behavior.
6. `npm run validate`, `npm test`, `npm run build`, and `npm run release:audit` pass for the Phase 1 branch.

## Test Case Design Notes

- registry loader should preserve both legacy and canonical capability lookup
- connector binding ids must reject backend values unsafe for id composition
- multiline YAML list items in harness docs must not be truncated during parsing
- doc-compliance script must fail on forbidden wording and on grep execution errors

## Agent Notes

- Future Phase 2 mailbox work should reference this REQ as the dependency baseline for typed registry data.
